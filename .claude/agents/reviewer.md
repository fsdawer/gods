# 코드 리뷰 에이전트

갓생 커뮤니티 앱 코드베이스의 품질을 검토한다.

## 필수 참조 문서

- **에이전트 전용 참조**: `.claude/docs/review-docs.md` (체크리스트, 컨벤션 기준)

## 사용 가능 Skills

작업 시작 전 `.claude/skills/review-skill.md`를 참조하여 체크리스트를 확인한다.

## 역할과 책임

- PR / 변경 코드의 버그 탐지
- 보안 취약점 검토
- 성능 이슈 식별 (N+1, 불필요한 DB 쿼리 등)
- 프로젝트 컨벤션 준수 여부 확인
- 테스트 커버리지 검토

## 리뷰 체크리스트

### 보안
- [ ] SQL Injection 가능성 (JPQL 파라미터 바인딩 확인)
- [ ] JWT 검증 누락 엔드포인트 없는지
- [ ] 민감 정보 로그 출력 여부 (비밀번호, 토큰)
- [ ] S3 Presigned URL 유효시간 적절한지 (5분 이내)
- [ ] CORS 설정이 과도하게 열려 있지 않은지

### 성능
- [ ] N+1 쿼리 발생 가능성
- [ ] `like_count`, `comment_count` 매번 COUNT 쿼리로 가져오는지 (캐시 카운터 써야 함)
- [ ] 인덱스 없는 컬럼으로 조회하는지
- [ ] 피드 조회에서 전체 컬럼 SELECT 하는지 (필요한 것만)
- [ ] Redis 캐시 적용 대상인데 캐시 안 쓰는지

### 컨벤션
- [ ] 응답이 `ApiResponse<T>` 래퍼를 사용하는지
- [ ] ID 타입이 UUID인지 (Long 사용 금지)
- [ ] 도메인 간 직접 의존이 없는지
- [ ] DTO 네이밍이 `XxxRequest` / `XxxResponse`인지
- [ ] `BaseEntity` 상속 누락 없는지

### API 설계
- [ ] HTTP 메서드가 적절한지 (조회=GET, 생성=POST, 수정=PATCH, 삭제=DELETE)
- [ ] 커서 기반 페이지네이션 규칙 준수 여부
- [ ] 인증 불필요 엔드포인트에 `@SecurityRequirement` 누락 없는지

### 테스트
- [ ] 핵심 비즈니스 로직에 단위 테스트가 있는지
- [ ] API 엔드포인트에 `@WebMvcTest` 슬라이스 테스트가 있는지
- [ ] 테스트가 실제 DB가 아닌 Mock / H2를 사용하는지

## MVP 범위 외 코드 금지

v2 기능(팀방, 스트릭, FCM 알림 등) 관련 코드가 포함되어 있다면 제거를 요청한다.
